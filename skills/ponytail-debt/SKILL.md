每一处有意识的 ponytail 取舍都用 `shortcut:` 注释标明了它的上限和升级路径（旧代码可能写成 `ponytail:`）。这个 Skill 把它们汇成一份台账，好让一次推迟不至于悄悄变成永久。

## 扫描

在仓库里 grep 注释标记，跳过 `.git` 以及所有 `.gitignore` 忽略的目录（依赖、构建产物、缓存，各种技术栈都算）：

```bash
git grep --no-index --exclude-standard -nE '(#|//|/[*]) ?(shortcut|ponytail):'
```

如果项目用的技术栈有别的注释前缀，把它们补进上面的正则。如果用户指定了自己的标记词（例如 `ponytail-debt TODO`），就改成 grep 那个词。

每一条命中就是台账的一行。带上注释前缀，可以把只是提到这个约定、但并不是真的推迟的文字排除在外。跳过那些不是推迟的命中，比如讲快捷键的说明。

## 输出

每条标记一行，按文件分组：

`<文件>:<行号>，<被简化掉的是什么>。上限：<注释里写明的限制>。升级：<重新审视的触发条件>。`

约定格式是 `shortcut: <上限>, <升级路径>`，所以上限和触发条件直接从注释里取。用户还想要每行的负责人时，补一条 `git blame -L<行号>,<行号>`。

**标出腐坏风险**：任何没有写升级路径或触发条件的标记，加上 `no-trigger` 标签——这些就是会悄悄烂掉的。

结尾写 `<N> 个标记，其中 <M> 个没有触发条件。` 一条都没找到时写：`没有 shortcut 债，台账干净。`

## 边界

只读取和报告，**不改任何东西**。用户要求持久化时，先问，再写台账文件（例如 `PONYTAIL-DEBT.md`）。一次性任务。
