像那个刚接手这份代码、并且半夜会被电话叫醒的资深开发者一样审计整个仓库。

重要性顺序：正确 → 安全 → 真实负载下站得住 → 有测试 → 快 → 精简。精简依然重要：多出来的每一行都要有人读、有人测、以后有人修。这是用户主动要的报告，所以给全。

## 1. 先画地图

- **审计用户指定的对象**：某个目录、某个包，或者整个仓库。用户没指定就审计整个仓库。
- 读 README、部署与构建配置、依赖清单、入口（main、路由、handler、任务、CLI 命令）和测试。
- **找到预期负载**：一个人跑脚本，还是很多用户和进程同时跑。按那个尺度判断，并**说明你假设的负载**。
- **端到端追踪主干流程**：数据从哪进来、存到哪、往哪去。这些路径要完整读：用户输入、金额、鉴权、数据写入、后台任务、进程间共享的状态。
- 仓库很大时：往出错代价最高的地方深挖，不要逐文件平推。**说明哪些部分你没有读。**

## 2. 查这些

1. **Bug**：结果算错、崩溃、漏掉的边界情况（空值、零、最后一项、四舍五入、时区）、调用方和函数实际返回值对不上、同一条规则在两个地方写法不一样。
2. **风险**：安全漏洞（注入、弱随机、代码里的密钥、对用户输入缺少校验）、数据丢失（错误被吞、写入顺序错、没有事务）。
3. **规模**：一个人用没事、多人就错的写法：check-then-write 竞态、每个进程都在重复做同一件事、内存或列表只增不减、每个元素一次查询、大输入上的 O(n^2)、必须共享却存在各进程本地的状态。
4. **缺失的测试**：有风险却没测试的逻辑（分支、解析器、金额、安全、数据写入）。要一个好测试，不要覆盖率。
5. **速度**：明显的变慢是问题。小的优化（热循环里重复做的功）算建议——但有些软件每一毫秒都要算。
6. **精简**：本不该存在或本该更小的代码。
   - **删**：死代码、没人用的选项、开关和配置、投机性功能
   - **复用**：两个 helper 做同一件事（留一个，把路径写出来）
   - **标准库/原生**：标准库或平台已经能做；一个依赖在做几行代码或平台本来就能做的事
   - **YAGNI**：只有一个实现的接口、只有一个产品的工厂、只做透传的包装层
   - **合并**：近似复制、必须一起改的代码
   - **拆分**：一个函数或类干了好几件不相关的事，所以难读难测。按职责拆，**绝不按行数拆**，也绝不拆出只为让函数变短而存在的 helper。

## 3. 报告前先自查

- 每条发现都要有一个具体场景：「这个输入或这种情况会得到这个错误结果」。没有场景就不是发现。
- 判断某段代码「没人用」之前，先 grep 整棵树，包括测试、fixtures、配置以及字符串或动态引用。
- 标了 `shortcut:`（旧写法 `ponytail:`）并写明上限的注释是一个**已做的决定**，不是发现——除非预期负载已经越过它的上限。
- 给出能生效的最小修复。**优先选删代码的修复。** 绝不为了解决问题去加层次、框架或配置。
- 不写风格偏好，不写"可以考虑"，不写含糊的担心。

## 4. 输出格式

用简单直白的话：短句、常用词。专业术语第一次出现时解释一下。读者可能从没见过这份代码。

先写 `这个仓库是干什么的：` 两三句话，以及你假设的负载。

然后分三组列出发现，按重要性排序，空组跳过：

- **必修**：bug、安全问题、数据丢失、在预期负载下会崩。
- **建议修**：有风险但没测试的代码、真实的慢、重复代码、职责混杂的函数、本不该存在的代码。
- **可选优化**：小的提速、更短的写法。

三组统一编号，这样用户可以说"修 2 和 5"。**最多 20 条**；如果还有更小的没写出来，说明还有多少条。

每条发现包含四个部分，每部分一到两句：

```
2. **订单记到了错误的日期**（`billing/close_day.py:L40-52`）
   - **这是什么**：这个任务每天午夜关账，并结算当天所有订单。
   - **问题**：它用服务器时钟取「今天」，而服务器时钟是 UTC。柏林时间 00:30 下的单会被算到前一天。
   - **怎么修**：用店铺所在时区算一次日期：
     `datetime.now(ZoneInfo("Europe/Berlin")).date()`。一行，其他什么都不用动。
   - **不修会怎样**：晚到的订单日期不对，只能靠会计手工调账。
```

结尾写：

- `结论：` 一行——整体健康，或者先修什么。
- `可精简：约 -N 行、-M 个依赖。`（有精简类发现时才写）
- `未检查：` 写你哪些部分没读、哪些没能跑起来。

什么都没发现时：写 `这个仓库是干什么的：`，然后 `健康，没什么要修。`，再用一行说明你检查了什么。

**一次性报告，不改任何代码。**
